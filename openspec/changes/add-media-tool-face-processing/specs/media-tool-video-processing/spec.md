## ADDED Requirements

### Requirement: 视频有界流式处理

系统 MUST 对第一条主视频流使用顺序解码、逐帧人脸处理和编码，不把整段视频、全部帧或全部原始字节装入内存，不生成完整图片序列。原视频每个有效展示帧 MUST 进入处理链，不能通过跳帧获得速度提升。

#### Scenario: 处理长视频
- **WHEN** 输入包含大量帧且配置允许的缓冲大小固定
- **THEN** 帧缓冲占用不会随视频帧数线性增长，全部有效展示帧按时间顺序处理

### Requirement: 保留可变帧率展示时间

系统 MUST 使用输入帧 PTS 与 time_base 保留展示时间，并正确换算到编码器和封装时间基，兼容 CFR 与 VFR。系统 MUST 不以平均 FPS 和帧序号重建 VFR 时间线。缺失必要时间戳且无法确定原时间线时 MUST 明确报错，不隐式假设固定帧率。

#### Scenario: 可变帧率素材
- **WHEN** 输入相邻帧的展示时间间隔不同
- **THEN** 输出保留各帧相对展示时间，在输出时间基舍入容差内保持输入时间间隔

#### Scenario: 编码时间基与封装时间基不同
- **WHEN** 编码器与输出容器使用不同 time_base
- **THEN** 输出包的时间戳正确换算，不产生非单调时间线或错误时长

### Requirement: 音轨保留与共同时间原点

系统 MUST 保留原输入全部音轨的顺序与音画相对起始偏移。与目标 MP4 兼容的音轨 MUST 优先复制，不兼容的音轨转 AAC；无音轨输入 MUST 正常输出无音轨视频。视频和音频 MUST 使用共同时间原点，不能分别归零或通过截短掩盖同步问题。

#### Scenario: 音频晚于视频开始
- **WHEN** 输入音轨起始展示时间比视频晚 500 毫秒
- **THEN** 输出保留该相对偏移，在编码格式允许的时间精度内保持同步

#### Scenario: 多音轨输入
- **WHEN** 输入有两条有效音轨
- **THEN** 两条音轨均进入输出并保持顺序，分别采用兼容复制或 AAC 转码

#### Scenario: 无音轨输入
- **WHEN** 输入只有主视频流
- **THEN** 输出正常可解码且没有人为创建的静音音轨

### Requirement: 视频方向与展示尺寸正确

系统 MUST 应用输入旋转信息后在正确展示方向执行人脸处理，并避免输出重复携带已应用的旋转变换。系统 MUST 保持正确展示尺寸与必要像素宽高比；编码约束要求奇数尺寸补边时 MUST 明确记录，不能静默裁剪。

#### Scenario: 手机竖屏旋转视频
- **WHEN** 输入通过旋转元数据表达竖屏方向
- **THEN** 输出以正确竖屏方向播放，检测和贴回坐标一致，不重复旋转

### Requirement: 输出编码与容器明确

成功处理的视频 MUST 默认输出 H.264 MP4，采用 `libx264`、CRF 18 和 preset medium，并允许配置合法编码参数。原 MP4 保留原名，其它容器使用完整原名加 `.mp4`。音轨合并 MUST 不再次编码已处理的视频流。首版 MUST 不宣称保留字幕或附加视频流。

#### Scenario: MOV 素材换脸输出
- **WHEN** 输入 `目录/a.mov` 有成功匹配换脸
- **THEN** 输出 `目录/a.mov.mp4`，包含已处理的 H.264 主视频和所需原音轨

#### Scenario: MP4 素材换脸输出
- **WHEN** 输入 `目录/a.mp4` 有成功匹配换脸
- **THEN** 输出路径为 `目录/a.mp4`，音轨合并不再次压缩视频流

### Requirement: 完整判断未匹配视频

系统 MUST 在完整处理全部帧后判断视频是否完全未匹配。未匹配时 MUST 丢弃临时编码结果，并按批处理策略原样复制输入容器或跳过，不能输出重新压缩的视频作为原样复制结果。

#### Scenario: 仅最后一帧匹配
- **WHEN** 视频前部没有匹配脸，但最后一个有效帧出现匹配脸
- **THEN** 视频视为需要转换并发布处理结果，不按未匹配复制或跳过

#### Scenario: 完整视频没有匹配
- **WHEN** 所有有效帧均正常处理且没有匹配脸，复制策略已开启
- **THEN** 临时编码结果丢弃，最终文件保持原名、容器和字节内容

### Requirement: SDR 范围和输出完整性校验

首版 MUST 对支持的 SDR 视频运行；检测到 HDR 或无法可靠处理的颜色格式 MUST 明确报告失败，不直接按普通 8 位 BGR 处理。最终视频 MUST 在发布前验证可以解码、包含预期流、展示帧数和时间线符合输入处理计划，并检查音画偏移与结束时间。

#### Scenario: HDR 输入
- **WHEN** 输入视频声明 PQ 或 HLG HDR 传递函数
- **THEN** 系统报告首版不支持 HDR，不输出偏色的 SDR 媒体并标记成功

#### Scenario: 音轨合并失败
- **WHEN** 临时视频生成成功，但合并或最终校验失败
- **THEN** 当前素材报告失败，不发布最终媒体文件
