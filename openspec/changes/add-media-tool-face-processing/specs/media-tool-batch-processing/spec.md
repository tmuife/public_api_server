## ADDED Requirements

### Requirement: 递归扫描真实素材

系统 MUST 递归扫描 `input_material_path`，以稳定顺序读取支持的静态图片和视频候选文件，并通过解码或探测确认类型。系统 MUST 忽略非素材文件，不跟随符号链接，不修改输入内容；损坏或不支持的候选素材 MUST 报告明确原因。

#### Scenario: 输入包含多级目录与其它文件
- **WHEN** 输入包含图片、视频、文本文件和多级子目录
- **THEN** 处理全部支持的素材并保留相对目录，文本文件忽略

#### Scenario: 文件扩展名与内容不符
- **WHEN** 一个 `.jpg` 文件无法作为支持的静态图片解码
- **THEN** 该文件报告失败，不发布媒体输出，也不把其记为正常未匹配

### Requirement: 静态图片方向与透明度正确

系统 MUST 支持静态 JPEG、PNG、WebP、BMP、单页 TIFF 和 HEIC，正确应用 EXIF 方向并转换为模型使用的 SDR 图像；PNG 等支持透明度的输出 MUST 保留原始透明通道。模型处理后的输出 MUST 不携带会再次旋转的旧方向信息或错误的色彩配置。动画图片与多页图片 MUST 明确报告不支持。

#### Scenario: 图片带有 EXIF 旋转
- **WHEN** 输入 JPEG 通过 EXIF 指定旋转方向
- **THEN** 人脸检测基于正确展示方向，输出打开后不重复旋转

#### Scenario: 透明 PNG 换脸
- **WHEN** 输入 PNG 包含透明通道并有匹配脸
- **THEN** 输出保持原始尺寸和透明通道，颜色内容完成换脸及所需增强

#### Scenario: 动画或多页图片
- **WHEN** 输入为动画 GIF、动画 WebP 或多页 TIFF
- **THEN** 系统报告不支持，不隐式只处理第一帧或第一页

### Requirement: 输出路径保持层次并检查冲突

系统 MUST 在输出根目录保持输入相对子目录。处理后的常见图片保持原名与支持的原格式；HEIC 输出完整原名加 `.jpg`；处理视频按视频规格映射；未匹配复制保留原名。系统 MUST 在处理前检查所有处理与复制候选输出之间的冲突，并考虑大小写不敏感文件系统；冲突 MUST 终止运行，不能按处理顺序覆盖。

#### Scenario: 输出嵌套素材
- **WHEN** 输入包含 `旅行/合影.png`，且该图片有匹配脸
- **THEN** 输出写到 `output_material_path/旅行/合影.png`

#### Scenario: 处理与复制路径可能冲突
- **WHEN** 输入同时包含 `a.mov` 和 `a.mov.mp4`，前者处理路径与后者原样复制路径相同
- **THEN** 运行在处理前报告两个来源与冲突路径，并以非零状态退出

### Requirement: 未匹配素材按配置复制或跳过

系统 MUST 支持 `unmatched_action=copy|skip`，默认 `copy`。正常完整处理后没有任何匹配换脸的图片或视频，在 `copy` 模式 MUST 按字节原样复制，在 `skip` 模式 MUST 不创建媒体输出；两者均记录独立状态。未匹配视频的判断 MUST 覆盖完整视频，不能用采样推断。

#### Scenario: 未匹配素材原样复制
- **WHEN** 一个支持且完整解码的素材没有匹配脸，并使用默认复制策略
- **THEN** 输出与原文件字节一致，不使用重新编码结果

#### Scenario: 未匹配素材跳过
- **WHEN** 未匹配素材使用 `unmatched_action=skip`
- **THEN** 不创建最终媒体文件，报告该素材因未匹配被跳过

### Requirement: 已有输出与原子发布

系统 MUST 默认 `overwrite=false`，对已有输出明确跳过并记录；`overwrite=true` 才允许替换。新输出 MUST 先关闭、校验，再通过输出同目录的临时文件原子发布，即使工作目录与输出目录跨文件系统也成立。失败 MUST 不留下可被误认成功的最终半成品，也不损坏原有输出。

#### Scenario: 不覆盖已有结果
- **WHEN** 目标文件已存在且未开启覆盖
- **THEN** 该文件跳过并记录存在性跳过，不把旧结果宣称为本次配置下重新验证成功

#### Scenario: 覆盖过程中编码失败
- **WHEN** 开启覆盖但新媒体在编码或校验中失败
- **THEN** 原有最终文件保持有效，新失败结果不发布

### Requirement: 文件级容错与运行报告

系统 MUST 支持 `on_error=continue|stop`，默认继续。文件失败时 MUST 记录输入、阶段和原因；继续模式处理其它文件但最终返回非零状态，停止模式在首个文件错误后停止。配置、模型初始化等全局错误 MUST 在处理前退出。系统 MUST 在输出根目录下的 `.media-tool-reports` 保存本次 JSONL 报告，包含状态、路径、参数、检测器、实际后端、帧数、匹配/替换数和耗时，不保存原始人脸或 embedding。

#### Scenario: 批次中一个文件损坏
- **WHEN** 连续三个素材的第二个文件损坏，且配置继续模式
- **THEN** 第一个和第三个可以完成，第二个记录失败，本次命令返回非零状态

#### Scenario: 全局模型初始化失败
- **WHEN** 模型文件存在但无法初始化
- **THEN** 系统不进入逐文件处理，不对每个文件重复尝试同一无效初始化

### Requirement: 临时目录只清理本工具创建的内容

系统 MUST 在 `work_dir` 下为运行和文件创建独立任务子目录，并在 `cleanup_work_dir=true` 时清理本次创建的内容。正常结束和中断 MUST 关闭媒体资源与子进程。系统 MUST 不递归清空整个用户工作目录，最终报告 MUST 保存在清理范围外。

#### Scenario: 工作根目录已有用户文件
- **WHEN** 工作根目录包含本次任务目录和用户原有文件
- **THEN** 任务清理只删除本次创建的目录，用户文件与运行报告保留

#### Scenario: 处理期间中断
- **WHEN** 用户中断正在处理的视频
- **THEN** 子进程和媒体资源关闭，当前文件不发布半成品，按清理配置处理本次临时目录
