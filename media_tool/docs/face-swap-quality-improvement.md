# 换脸质量改进方案：可配置模型与非正脸处理

日期：2026-10-05。状态：设计建议，尚未实现。

本文基于已实现并验证的 `media_tool`，以及本地 FaceFusion v4 的源码与前期图片对照。目标是在保留现有批处理能力的基础上，解决非正脸换脸时的明显失真，并提高融合自然度。本文中的新增配置、处理步骤和验收要求均为后续设计，不代表当前程序已经支持。

## 1. 需求与建议方向

需要满足两个核心需求：

1. 可以通过配置选择不同换脸模型，同一批素材能够分别使用不同模型进行比较。
2. 增加有针对性的前处理与后处理，改善侧脸、俯仰、遮挡、肤色边界及视频连续性。

建议保留 INSwapper 作为兼容基线，优先接入 HyperSwap 1a/1b/1c 256 作为候选；同时引入可靠关键点精修、姿态与质量判断、可见区域遮罩和受约束的增强。**对当前非正脸问题，模型适应能力、对齐可靠性和可见区域处理应优先于超分辨率与锐化。**

更高分辨率能够增加细节，但无法直接修复错误的鼻梁方向、被拉伸的嘴、重复的眼睛或错误的脸部轮廓。新的默认模型及处理参数需要经过侧脸素材验收后确定。

## 2. 当前实现与已有证据

### 2.1 当前链路

```text
原图 / 视频帧
  → SCRFD 或 YuNet 检测，输出五点关键点
  → 五点对齐 + ArcFace 身份识别与参考匹配
  → INSwapper 128 换脸
  → 矩形区域腐蚀、模糊并贴回
  → GFPGAN 512 增强
  → 固定椭圆遮罩贴回
  → 图片保存 / 视频编码
```

| 当前模块 | 与效果有关的行为 |
|---|---|
| [face_analyzer.py](../src/media_tool/face_analyzer.py) | 使用检测器五点做识别对齐，没有独立关键点精修 |
| [face_swapper.py](../src/media_tool/face_swapper.py) | 固定 INSwapper 128 输入、身份映射与几何遮罩贴回 |
| [alignment.py](../src/media_tool/alignment.py) | 五点二维相似变换，增强使用固定椭圆遮罩 |
| [face_enhancer.py](../src/media_tool/face_enhancer.py) | GFPGAN 固定噪声与统一增强融合比例 |
| [pipeline.py](../src/media_tool/pipeline.py) | 逐帧匹配，先换脸后增强，复用原始人脸关键点 |
| [config.py](../src/media_tool/config.py) | 尚无换脸模型选择、关键点精修或语义遮罩配置 |

现有媒体读写、原分辨率输出、音轨与时间戳处理、模型复用、原子发布和未匹配素材复制应继续保留。已有功能验证说明链路能够正确执行，但不能替代非正脸视觉质量验收。

### 2.2 前期图片对照的结论与边界

2026-10-02 的对照使用同一张近正脸素材及同一张替换照片，在 Linux CPU 上运行。当前输出被逐像素复现。使用当前 ArcFace 分析器测量结果与替换照片的余弦相似度：

| 方案 | 相似度 |
|---|---:|
| 当前 INSwapper 128，仅换脸 | 0.8825 |
| 当前 INSwapper 128 + GFPGAN 70% | 0.8340 |
| FaceFusion INSwapper 128，仅换脸 | 0.8715 |
| FaceFusion INSwapper，Pixel Boost 256 | 0.8742 |
| FaceFusion HyperSwap 1a 256，仅换脸 | 0.6988 |
| FaceFusion HyperSwap 1a 256 + GFPGAN 70% | 0.6581 |

该样例中，HyperSwap 细节表现更好，但 INSwapper 的身份特征更接近替换照片；GFPGAN 提高清晰度的同时降低了这一相似度。数值不是质量百分比，也不是成功率，且评估模型与换脸身份特征体系相关，存在评价偏向。

两边的检测权重、对齐和模型导出文件有所不同，这不是所有变量均受控的评测。**上述试验未验证严重侧脸，不能据此声称 HyperSwap 或 Pixel Boost 已解决当前非正脸失真。** 后续应以用户出现问题的图片和连续视频为主要验收集。

## 3. 非正脸为什么更容易失真

以下是结合当前结构需要重点排查的机制；具体样例的主因仍需通过中间结果定位。

| 机制 | 非正脸下的表现 | 改进方向 |
|---|---|---|
| 检测五点不可靠 | 不可见眼睛、嘴角被猜测，鼻尖或眼睛位置偏移 | 独立关键点精修、置信度与可见性判断 |
| 二维对齐的能力限制 | 侧脸的透视缩短无法被旋转、缩放和平移消除 | 按模型约定对齐，增加姿态判断，评估姿态适应能力 |
| 模型自身的姿态覆盖不足 | 对齐合理但输出仍出现五官拉伸或错误补全 | 在固定姿态分组中比较模型，限定可处理范围 |
| 128 分辨率限制 | 侧脸眼睛、鼻翼和嘴角的小区域细节更少 | 原生 256 模型或适度 Pixel Boost |
| 几何遮罩不理解轮廓 | 生成内容覆盖背景、耳朵、头发或前景遮挡物 | 可见区域、语义与遮挡遮罩 |
| 增强放大错误 | 把错误眼睛、牙齿或鼻翼变得更清楚 | 几何质量判断先于增强，限制增强强度与范围 |
| 视频逐帧独立处理 | 转头过程中五官与边界跳动，换脸开关反复变化 | 身份关联、关键点与遮罩稳定、匹配迟滞 |

应区分三类角度：偏航 yaw 是左右转头，俯仰 pitch 是抬头低头，翻滚 roll 是画面内倾斜。检测时把图像旋转 90° 或 180°主要应对 roll，不能解决 yaw 造成的自遮挡。

五点拟合误差较小也不意味着侧脸有效：模型可能用猜测的隐藏点完成了数学上合理的拟合。68 点或稠密关键点同样可能在大侧脸上失效，不能无条件替换原始五点。

建议为问题样例保存可选调试视图：原始检测点、精修点、模型输入裁剪、未贴回的换脸结果、有效遮罩、增强前后结果。如果模型输入已经歪斜，优先修前处理；如果输入合理而模型输出畸变，优先比较模型；如果裁剪结果合理而贴回穿帮，优先修遮罩与融合。

## 4. 可配置换脸模型

### 4.1 候选与接入顺序

| 模型 | 原生尺寸 | 建议定位 | 需要验证 |
|---|---|---|---|
| `inswapper_128` | 128×128 | 保留当前行为，作为身份与兼容基线 | 侧脸上限、Pixel Boost 收益 |
| `hyperswap_1a_256` / `1b` / `1c` | 256×256 | 首批新增候选，三个变体分别比较 | 左右侧脸、俯仰、身份和口型 |
| `alphaface_256` | 256×256 | 第二批候选 | 非正脸泛化、身份输入、后端兼容 |
| Ghost / SimSwap 等 | 按具体模型 | 前两组仍不能满足时再扩展 | embedding converter、模板和输出归一化 |

不同模型年份、原生尺寸或 FaceFusion 默认选择都不能代替本项目验收。FP16 主要涉及精度表示、内存和后端执行，不是侧脸质量增强算法。

首版采用**一个任务显式选择一个模型**。不默认同时加载全部模型，不按每帧姿态自动切换模型。逐帧切换可能造成身份、纹理和肤色闪烁；若以后需要自动选择，应优先按整段镜头或稳定轨迹选择，并单独验证切换过渡。

### 4.2 模型适配不能只替换权重路径

每个受支持模型应有明确、经过验证的配置与适配逻辑：

| 适配内容 | 要求 |
|---|---|
| 权重与附属模型 | 本地路径、版本、校验值、所需 converter，启动时检查 |
| 模型输入 | 输入名称、维度、类型，按名称和模型约定绑定 |
| 身份输入 | 区分原始 embedding、归一化 embedding、INSwapper 映射、converter 或照片裁剪 |
| 对齐 | 使用该模型约定的模板、裁剪范围和原生尺寸 |
| 图像预处理 | RGB/BGR、数值范围、均值与标准差明确配置 |
| 输出处理 | 按模型约定反归一化，检查尺寸与有限值 |
| 执行后端 | 检查 CPU/CoreML 及精度兼容，记录实际执行情况 |

当前分析器只保留归一化 embedding，流水线缓存的是 INSwapper latent。后续需要根据模型需要保留原始与归一化特征，或保存经过验证的照片裁剪，再由所选模型准备身份输入。不能把 INSwapper latent 直接交给其他模型。

建议使用少量显式模型配置和清晰的适配函数，复用现有 ONNX 会话管理。暂不建立动态插件系统，也不引入 FaceFusion 的会话、API 和任务框架。

### 4.3 拟新增配置

下表为配置设计，不是当前可用参数。保留现有默认行为作为兼容基线，质量配置在验收后单独确定。

| 拟新增配置 | 设计含义 |
|---|---|
| `face_swapper_model` | 选择已支持模型，兼容默认值为 `inswapper_128` |
| `face_swapper_pixel_boost` | 所选模型支持的裁剪输出尺寸；默认等于原生尺寸 |
| `face_landmark_model` | 不精修或选择受支持关键点模型 |
| `face_mask_types` | 选择边界、可见区域、遮挡、语义遮罩 |
| `face_mask_blur` / `face_mask_padding` | 按裁剪尺度控制边缘羽化和边距 |
| `face_occluder_model` / `face_parser_model` | 使用相应遮罩时才要求对应权重 |
| `face_color_match` | 关闭或使用经验证的局部颜色校正 |
| `face_quality_policy` | 对不可信几何结果采取保留原脸或明确失败等策略 |
| `expression_restore_enabled` | 可选表情恢复，默认关闭 |

现有 `enhance_enabled` 和 `enhance_blend` 继续使用，不增加含义重复的增强参数。模型原生输入尺寸来自模型配置，不允许通过任意尺寸参数把 128 模型当作 256 模型调用。

未知模型、不支持的 Pixel Boost 尺寸、缺少权重或附属 converter 应在检查阶段明确失败。显式选择的模型不能静默替换成其他模型；`auto` 后端在已知兼容问题下切 CPU 可以保留，但必须报告，这与更换模型是两回事。

## 5. 前处理：提高非正脸输入可靠性

### 5.1 检测与关键点精修

继续保留 SCRFD 基线，仅在漏检或低质量检测时评估多尺度回退、局部重检或第二检测器。不要把统一增大检测尺寸、降低阈值当作侧脸修复方法。

前期替换照片在输入 480 时检测置信度约 0.806，在 640 时约 0.396，会被当时的 0.6 阈值过滤。这说明尺寸变化需要实测，不能假定越大越可靠。

借鉴 FaceFusion 的关键点精修与置信度回退方法，优先评估 2DFAN4 或其他经过侧脸验证的关键点模型。精修后检查点位置信度、可见性、几何一致性及裁剪结果；只有可靠时才更新对齐点。精修失败而检测五点也不可靠时，应进入质量策略，不应强行回退后继续生成。

识别与换脸可使用经过验证的精修点，但必须分别保持 ArcFace 与换脸模型自己的模板。改变对齐方式后重新注册参考特征，并重新校准匹配阈值。

### 5.2 姿态判断与处理范围

在可靠关键点基础上评估头部姿态估计。可采用专用姿态模型，或用可靠点与标准三维脸模型做近似姿态求解；其误差与脸型、遮挡和相机有关，应保留置信度。不能用二维眼睛连线角度代替 yaw。

按姿态、遮挡、可见点数量、裁剪有效范围和模型输出质量共同决定是否处理。不要仅凭一个未经标定的角度阈值跳过全部侧脸。

对不可信结果建议提供“保留该脸原始像素并记录原因”的策略，也可由用户选择严格失败。视频里必须报告未处理帧，避免用跳过所有困难帧制造虚假的质量提升。其他可信人脸可以按既定错误策略继续处理，匹配数、实际换脸数和增强数分别统计。

接近纯侧面、严重仰头或大面积遮挡可能超出现有二维换脸模型的可处理范围。若候选模型仍不能满足要求，三维几何约束或针对目标场景训练应作为独立研究项；不建议默认先把侧脸生成成正脸再换脸，因为这会增加不可见区域幻觉和逆变换误差。

### 5.3 替换身份照片

当前 `source_face` 是被匹配人物的参考集合，`target_face` 才是替换身份；FaceFusion 的 source 指替换身份。接入时必须明确映射。

先使用清晰、无强遮挡、光照均匀且面部尺寸足够的替换照片。后续可以显式增加同一替换身份的多照片模式，评估按质量加权的特征聚合；当前“恰好一张替换照片”契约在默认模式下保留。

多角度照片有助于降低单张身份提取的偏差，但 embedding 平均不会自动提供真实侧脸纹理，也不能修复目标画面的几何失真。以照片裁剪为输入的模型需要单独定义照片选择方法，不能照搬 embedding 聚合规则。

## 6. 后处理：保护轮廓、遮挡和表情

### 6.1 组合有效遮罩

建议由三类信息约束最终可替换范围：

```text
有效遮罩 = 边界限制 ∩ 可信面部可见区域 ∩ 遮挡保护
```

边界遮罩负责裁剪边缘和羽化；面部区域可以来自可信关键点区域或语义解析；遮挡保护从原始素材预测，避免手、头发、眼镜等前景被生成内容覆盖。可先评估 XSeg 遮挡模型和 BiSeNet 面部解析。

对侧脸，语义可见区域尤其重要。仅对全部 68 点求凸包仍可能包含模型猜测的隐藏半张脸，因此不能把凸包当作充分的可见性判断。眼镜、口腔和面部饰物也需要明确保留或替换策略，不能假定解析模型能精确保住每个细节。

遮罩可基于原图和生成结果共同检查，但原始前景保护不能被生成结果重新判定为可替换。两边几何差异过大时应触发质量判断，不能只靠缩小遮罩掩盖畸形。

换脸和增强的裁剪模板不同，遮罩应通过原图坐标正确映射，不能直接复用相同尺寸数组。增强的有效区域必须受共同可见区域与遮挡保护约束，避免第二次贴回破坏第一次保护。羽化尺度应跟随人脸大小，并检查是否产生双轮廓或背景泄漏。

### 6.2 颜色与光照校正

先保持模型要求的输入归一化，不在换脸前默认强行改变画面色彩。换脸后可在可信皮肤区域内评估受限的 Lab 颜色统计或亮度、色度校正，并排除嘴、眼、头发、眼镜和高光。

校正目标是保留原镜头光照并减少接缝，不是把替换照片的光照复制到素材中。限制校正幅度，视频中平滑校正参数。全脸直方图匹配可能压平阴影或引入色偏；Poisson 融合也可能改坏肤色和细节，均应作为对照候选而非默认保证。

优先从受限颜色校正加尺度自适应羽化开始；仍有边界问题时再比较多频段融合。颜色处理不能修复五官方向和三维轮廓。

### 6.3 增强与表情恢复

将增强视为可选细节恢复，先比较关闭、0.3、0.5、0.7 等强度。高质量特写和大姿态帧不应默认使用同一强度；几何失败结果不进入增强。

GFPGAN 保留固定噪声。CodeFormer、GPEN 等可以作为后续候选，但新增模型仍须同时评估身份、几何和视频稳定性。增强模型的 fidelity/weight 与像素融合比例含义不同，不能混用。

针对说话和眨眼，可评估 LivePortrait 表情恢复。它从原始素材提取表情，再应用到换脸结果，会增加计算与生成误差；大侧脸、遮挡下也可能失败。需要单独开关及强度控制，不能用保留原嘴像素作为所有场景的默认方案，否则可能残留原人物特征并产生接缝。

推荐的逻辑顺序为：换脸裁剪生成 → 几何质量判断 → 可选表情恢复与增强 → 局部颜色校正 → 受共同遮罩约束的最终融合。不同模型需要独立裁剪时，各阶段保持正确的坐标映射，尽量减少整帧反复裁剪与插值。表情恢复和增强的具体先后需通过对照确定。

## 7. 视频自然度与时序处理

视频是独立的质量问题，即使每帧静态图都能接受，连续播放仍可能出现闪烁。

建议基于框位置与原始身份特征建立轨迹，并对可信轨迹做关键点、遮罩边缘和颜色校正参数的轻量平滑。匹配采用进入/退出不同条件或短窗口确认，减少阈值附近反复切换。平滑应能跟随真实转头和说话，避免把快速运动抹成拖影。

只补偿短暂、可信的检测缺口。长时间遮挡、出画或切镜应结束轨迹并重置状态，不凭旧关键点持续换脸。不要直接把上一帧换脸像素混到当前帧，会在转头时产生重影。

FaceFusion 的轨迹关联主要使用框重叠，并对缺口插值，可借鉴其基础流程，但多人交叉时仍需要身份约束。保持现有有界帧缓冲，不把完整视频加载到内存。

## 8. 与现有工程结构的衔接

```text
原始素材与替换身份
  → 检测 / 可信关键点 / 姿态与质量信息
  → 原始画面身份匹配与可选轨迹关联
  → 所选模型的身份准备、专用对齐与推理
  → 输出几何质量判断
  → 可选表情恢复 / 增强 / 颜色校正
  → 共同可见区域与遮挡保护下的融合
  → 现有媒体输出与报告
```

模型适配负责自身的身份输入、预处理、推理和反归一化；公共处理负责原始几何、遮罩、融合和质量记录。避免每新增一个模型就复制一套视频读写与融合流程。

当前 `FaceSwapper.swap()` 把推理和整帧贴回放在一起。后续可在保留兼容行为的前提下，让内部阶段传递生成裁剪、变换和有效区域，使后处理能复用这些信息。默认未开启新增功能时，INSwapper 基线应仍可重现。

不需要为每一步创建抽象基类；行为真正重复且有利于阅读时再提取公共方法。先支持少量模型和处理组合，避免一次构建复杂的任意处理器图。

运行报告建议补充模型与权重版本、关键点方式、各阶段开关、实际后端、质量跳过原因及计数、阶段耗时。调试图片按需生成，报告继续不保存 embedding。

## 9. 分阶段推进

| 阶段 | 工作 | 完成判断 |
|---|---|---|
| A：定位与基线 | 收集实际非正脸失败素材，比较增强前后及中间裁剪 | 能区分对齐、模型生成、遮罩或增强的主要问题 |
| B：模型可配置 | 保留 INSwapper，接入 HyperSwap 三个变体，明确输入适配与检查 | 同一组素材可复现各模型结果，原有行为不回归 |
| C：非正脸基础处理 | 可信关键点、姿态质量判断、语义可见区域、遮挡保护 | 侧脸严重几何失真减少，保留原脸率同步报告 |
| D：自然度与视频 | 受限增强、颜色校正、可选表情恢复、时序稳定 | 连续转头与说话场景改善，遮挡和切镜无明显回归 |
| E：目标设备验收 | 在 M1 上比较 CPU、CoreML/MPS 的可用性、性能与内存 | 实际素材稳定运行，后端回退可解释 |

若阶段 A 已显示对齐是主要问题，可提前做关键点实验；若输入合理但模型输出严重畸变，则先扩大模型比较。Pixel Boost 在细节确实是瓶颈时加入，不以它替代阶段 C。

## 10. 验收方法

### 10.1 固定素材与对照方式

使用同一批替换身份、原图和视频，以不同输出目录隔离配置。当前 `overwrite=false` 会跳过已有结果，不能仅改变参数后复用旧输出目录来判断效果。

建议固定至少 20 张图片和 6 段连续短视频，覆盖左右转头、抬头低头、说话眨眼、手和头发遮挡、眼镜、暗光、小脸、多人交叉与切镜。角度分组可暂用近正脸、小于约 30°；中等偏航约 30°～60°；大偏航约 60°以上，同时单独标记 pitch 和遮挡。这些是测试分组，不是已经校准的运行门限，姿态不可靠时采用人工标签。

先关闭增强比较换脸模型，再逐项加入关键点、遮罩、增强、颜色和时序处理。变更对齐时承认它同时影响身份提取，不把差异全部归因于模型。保留原始画面、当前版本和候选结果，既查看放大裁剪，也以正常速度播放整段视频。

### 10.2 评估维度与准入

| 维度 | 观察或测量内容 |
|---|---|
| 非正脸几何 | 拉伸、重复五官、鼻嘴方向错误、面部轮廓异常的比例 |
| 身份相似 | 人工判断与 ArcFace 诊断，按姿态分组，必要时用另一识别器交叉评价 |
| 表情与姿态 | 张嘴、眨眼、视线和原始头部朝向的保留 |
| 融合自然度 | 皮肤边缘、脸颈颜色、背景泄漏、遮挡物是否保留 |
| 视频连续性 | 转头闪烁、漏换、身份切换、平滑滞后与重影 |
| 覆盖率 | 匹配帧中实际处理比例，以及保留原脸或失败的原因 |
| 运行成本 | 端到端 FPS、阶段耗时、峰值内存、实际后端 |

默认模型的准入要求应是：在中等和大角度分组中，人工标注的严重失真率相对当前基线下降；近正脸身份和表情无明显回归；遮挡穿帮和视频闪烁不增加。严重失真率同时按已处理样本统计，覆盖率按全部匹配样本统计，避免靠大量跳过通过验收。

建议在基线标注后确定具体改善目标、最低覆盖率和性能预算。当前缺乏侧脸样本统计，不设没有依据的身份阈值或 FPS 保证。现有功能测试继续作为回归检查；新增模型的输入输出和真实推理检查，加上人工视觉验收，分别验证工程正确性与效果。

## 11. 成本、能力边界与资料依据

Pixel Boost 对 INSwapper 从 128 提到 256，每张脸需要 4 次换脸推理；到 384 是 9 次，到 512 是 16 次。关键点、解析、遮挡和表情模型也增加延迟与内存，因此只加载启用且选定的模型。前期 Linux CPU 视频约 0.35 FPS 的结果不能用于预测 M1 性能。

自然度、身份相似度与处理覆盖率可能互相制约。若大侧脸输入超出所有候选模型能力，应明确记录并提供保留原脸或严格失败策略，而不是无限加大增强或融合强度。

模型使用条件按代码和权重分别核对。FaceFusion 本地元数据将 INSwapper、ArcFace 等标为 Non-Commercial，HyperSwap 标为 ResearchRAIL，项目代码标为 OpenRAIL-AS；具体接入依据原始发布条款与所用版本确认。

FaceFusion 对照版本固定为 `9cedad7d2c6f8534f20f66e425d113a655042b07`。该版本支持的功能不等于默认启用：默认遮罩为 box，跟踪分数为 0，表情恢复和增强需要选择对应处理器。
