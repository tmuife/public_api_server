# 换脸效果提升改造 TODO

> 目标：在现有 `insightface + inswapper_128` 方案上，优先提升“准确率、稳定性、观感”，并保持实时性可接受。

## 0. 现状基线与目标指标

- [ ] 建立现状基线（必须先做）
- [ ] 明确可量化目标（每项要有阈值）

### 基线建议采集（当前版本）

- [ ] 数据集A：单人正脸（白天/室内）
- [ ] 数据集B：多人同框（2-5人）
- [ ] 数据集C：大姿态（侧脸、低头、抬头）
- [ ] 数据集D：遮挡（口罩、手挡、眼镜）
- [ ] 数据集E：运动场景（快速移动、镜头抖动）

### 建议KPI

- [ ] 误替换率（False Swap Rate）
- [ ] 漏替换率（Missed Swap Rate）
- [ ] 视频闪烁率（相邻帧身份抖动）
- [ ] 人脸边界自然度主观评分（1-5）
- [ ] 平均推理耗时（ms/frame）
- [ ] 端到端FPS（含解码、推理、编码）

## 1. P0：低成本高收益（优先做）

### 1.1 目标身份匹配阈值重标定

- [ ] 不再使用固定经验阈值，基于样本做阈值标定
- [ ] 分别统计“同人距离分布”和“异人距离分布”
- [ ] 依据业务目标选择阈值（偏召回 or 偏精准）
- [ ] 输出阈值报告（建议值、风险场景、回退值）

验收标准：

- [ ] 在验证集上误替换率下降
- [ ] 漏替换率可控（按业务目标约束）

### 1.2 多人场景替换策略修正

- [ ] 当前命中后立刻返回的逻辑改为“遍历所有检测脸并按策略替换”
- [ ] 一帧内允许替换多个命中目标
- [ ] 设置每帧最大替换人数（防止误伤扩大）
- [ ] 加入最低检测置信度阈值（低置信不替换）

验收标准：

- [ ] 多人同框视频中，目标人物替换覆盖率明显提升
- [ ] 非目标人物误替换不明显增加

### 1.3 人脸输入质量门控

- [ ] 对 source/target 注册图做人脸质量检测（最小分辨率、清晰度、姿态）
- [ ] 拒绝低质量模板图并提示重传
- [ ] 模板图只取“最佳脸”（最大面积+高置信+低姿态角）

验收标准：

- [ ] 模板注册质量波动引起的结果不稳定显著减少

### 1.4 运行时稳定性与容错

- [ ] 避免推理失败直接中断流程，统一失败回退策略（返回原帧+错误计数）
- [ ] 异常日志结构化（请求ID、帧序号、耗时、错误类型）
- [ ] 对空检测结果、模型异常、编码失败做统一处理

验收标准：

- [ ] 长视频处理无明显崩溃/卡死
- [ ] 关键异常可追踪可复现

## 5. 风险与边界

- [ ] 极端侧脸/遮挡场景仍可能失败，需要业务上允许降级（返回原帧）
- [ ] 多人高相似度人脸可能出现误匹配，需要更严格阈值+跟踪联合
- [ ] 增强模型会增加延迟，需要设置可开关策略
- [ ] GPU/ONNX Runtime版本变化可能影响性能与稳定性
