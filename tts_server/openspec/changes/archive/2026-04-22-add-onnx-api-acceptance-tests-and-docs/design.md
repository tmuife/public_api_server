## Context

前两步实现聚焦“在当前项目中能跑且兼容 OpenAI 调用”，但还缺少稳定回归与交付门禁。
鉴于参考目录会删除，验收体系必须建立在当前项目本地代码上，不能依赖外部目录存在。

## Goals / Non-Goals

**Goals:**
- 建立当前项目可重复执行的 ONNX OpenAI API 验收基线。
- 覆盖“删除参考目录后”的独立运行验证。
- 将关键运行假设沉淀到文档，减少后续误用。

**Non-Goals:**
- 不在本 change 中引入复杂性能压测平台。
- 不在本 change 中覆盖所有语言/voice 的主观音质评测。
- 不在本 change 中扩展新业务接口。

## Decisions

- 决策 1：测试分为“接口契约测试 + 独立性测试（无参考目录）”。
  - Rationale: 同时保证 API 行为与部署独立性。
- 决策 2：自动化测试与手工脚本并行。
  - Rationale: 自动化保障回归，手工脚本便于快速排障。
- 决策 3：文档增加“支持矩阵 + 删除参考目录说明 + 验收步骤”。
  - Rationale: 明确边界，避免团队误将参考目录当生产依赖。

## Risks / Trade-offs

- [Risk] 集成测试加载模型耗时，影响开发反馈速度。
  - Mitigation: 区分快速冒烟与完整回归两档测试。
- [Risk] CI 与本地依赖差异引发偶发失败。
  - Mitigation: 固定关键版本并记录环境要求。
- [Risk] 文档滞后于实现变更。
  - Mitigation: 将 README 更新纳入验收清单硬性项。

## Migration Plan

- 第一步：补齐当前项目最小自动化用例与 fixture。
- 第二步：补充 curl/SDK 冒烟脚本与执行说明。
- 第三步：在发布流程加入“删除参考目录后验收”门禁。
- 回滚策略：若门禁阻塞发布，临时降级为手工验收并记录偏差。
